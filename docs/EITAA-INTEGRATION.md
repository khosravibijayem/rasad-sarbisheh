# بررسی فنی اتصال ایتا

این سند بر اساس سورس فعلی EitaaBun بررسی شده است؛ هنوز به معنی اتصال فعال حساب ایتا نیست.

## APIهای تأییدشده در سورس

- ارسال کد ورود: `POST /eitaa/auth/sendCode` با `{"phone":"+98..."}`
- ورود با کد: `POST /eitaa/auth/login` با `{"phone":"+98...","code":"..."}`
- ورود دومرحله‌ای: `POST /eitaa/auth/loginByPass`
- بازیابی نشست: `POST /eitaa/auth/loadSession`
- دریافت گفتگوها: `POST /eitaa/messages/dialogs` با `{"phone":"+98...","date":0}`
- دریافت پیام‌های یک کانال: `POST /eitaa/messages/read` با شناسه کانال، نوع `channel`، `offset` و `size`.

پاسخ dialogs شامل `dialogs`، `messages`، `chats` و `users` است. پیام‌های history شامل شناسه، متن، تاریخ، فرستنده، گیرنده و رسانه هستند.

## محدودیت‌هایی که باید قبل از استفاده رفع/آزمایش شوند

1. EitaaBun به Bun نیاز دارد و سرور Express آن روی پورت 1234 اجرا می‌شود؛ PHP اشتراکی به‌تنهایی میزبان مناسبی برای آن نیست.
2. مدیر نشست در `SessionManager` فقط یک Map حافظه‌ای است. بعد از خاموش/راه‌اندازی مجدد پردازش، نشست فعال در حافظه باقی نمی‌ماند و باید loadSession درست کار کند.
3. `getDialogs` در نسخه بررسی‌شده فقط 100 گفتگو را می‌گیرد؛ برای پوشش همه کانال‌ها باید صفحه‌بندی/تکرار با تاریخ آخرین پیام پیاده‌سازی و آزمایش شود.
4. `loadSession` در مسیر فایل ناموجود پاسخ خطای کامل و قابل اتکایی نمی‌دهد؛ باید اصلاح شود.
5. قبل از نگهداری اطلاعات ورود، باید API پشت HTTPS و دسترسی محدود باشد؛ توکن‌ها و فایل نشست نباید در مخزن Git یا گزارش‌های عمومی قرار گیرند.
6. باید با حساب آزمایشی بررسی شود که کانال‌های خصوصی عضو‌شده نیز در dialogs ظاهر می‌شوند و تاریخچه قابل خواندن است. این مورد را صرفاً از روی مستندات نمی‌توان تضمین کرد.

## معماری لازم برای نسخه کامل

- پنل PHP فعلی: نمایش خبر، فیلترها، ذخیره JSON و گزارش روزانه.
- سرویس Bun دائمی: ورود ایتا، نگهداری امن نشست، دریافت دوره‌ای dialogs و تاریخچه کانال‌ها.
- پل امن به `ingest.php`: ارسال خبرهای جدید با شناسه یکتا؛ پنل خبر تکراری را حذف می‌کند.
- زمان‌بند روی همان میزبان دائمی: اجرای چرخه دریافت؛ GitHub Actions جایگزین پردازش دائمی یا محل امن نگهداری نشست نیست.

تا وقتی میزبان دائمی Bun و ورود واقعی با حساب کاربر آزمایش نشده، نباید ادعای پایش خودکار یا پوشش همه کانال‌ها کرد.
